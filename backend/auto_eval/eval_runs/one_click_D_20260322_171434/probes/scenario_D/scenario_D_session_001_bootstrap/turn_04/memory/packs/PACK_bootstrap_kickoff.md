## narrative（给论文/组会的叙事骨架）
### 1) 这个包测什么
这个包不测实验结论本身，而是测这个 workspace 能否先完成以下三件 bootstrap 工作：
1. 把上传文件分成：**权威来源 / Pack seed / 参考素材**；
2. 判断当前**最值得优先整理的 Pack 类型**；
3. 防止容器退化成“普通写作摘要”或“实验待办清单”。

### 2) 这个 workspace 的职责边界
- 这是一个**写作/Pack 容器**；
- 当前职责不是重写整套论文，也不是重读全部实验与全部文献；
- 当前职责是先建立：
  - 交付件优先级；
  - 文件权威性分层；
  - 可复用 Pack 的范围与边界。

### 3) 优先整理哪类交付件
当前建议的起步优先级如下：
1. **章节主线类交付件**（最高优先）
   - 目标：先定义 thesis/proposal/group meeting/figure-layout 共享的上层主线；
   - 原因：复用范围最大，后续图组缺口与组会结构都能从这里派生。
2. **机制子包类交付件**
   - 目标：把高价钴生成与证据链收束成可挂载到第一章的机制 Pack；
   - 原因：已有较强 seed，但不应直接越级统领整篇 thesis。
3. **图组缺口类交付件**
   - 目标：在章节主线确定后，再做“章节 -> claim -> 图组 -> 缺口”的矩阵；
   - 原因：避免一上来就掉进补图/补实验清单。
4. **组会交付件**
   - 目标：从章节主线和图组缺口压缩派生；
   - 原因：属于派生层，不应作为 bootstrap 起点。
