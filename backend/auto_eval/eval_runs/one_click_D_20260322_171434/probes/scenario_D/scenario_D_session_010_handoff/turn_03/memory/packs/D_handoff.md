# D_handoff
> 用途：把这个 writing workspace 交给另一个模型时，先用这份文件判断：
> 1) 哪些文件优先读；
> 2) 哪些文件只是中间态；
> 3) 哪些文件只能作排版/风格参考；
> 4) 哪些内容暂时不能写死。
>
> 证据边界：本 handoff 基于本 workspace 中已读的 markdown/pack 文件形成；对 `.pptx / .docx / .pdf` 二进制文件的“版本角色”判断，来自相关 pack 文档与工作文档中的明示说明，而非本回合逐页核读。

## 二、仍有冲突的点
## 2.1 thesis 目前没有单一 final manuscript
- 目前最稳的 thesis authority 不是单一正文文件，而是：
  - `D_thesis_storyline_master.md`
  - `D_thesis_gapmap.md`
  - `99550dc7_【毕业论文】工作文档0305.md`
- 这意味着后续模型不能假设“thesis 已有唯一终稿”。
- 若要落到成文稿，必须先确认是继续写母版、工作文档，还是另有未读取的正式稿。
## 2.2 proposal 的“V3 PPT”与“final docx”语气边界不同
- `76bb19d2_开题报告-颜雍颀-V3.pptx` 是更锋利的答辩叙事版。
- `fde1237c_开题报告-颜雍颀(1).docx` 是更克制、可防守的正式 proposal。
- 因此后续写作时不能把 V3 的强机制表达直接平移进正式文本。
## 2.3 group meeting 与 literature report 的容器边界容易混淆
- 0305 大组会已经不是普通“逐篇平铺”的文献汇报，而是框架型组会包。
- `1c8b74da_literature_report_FINAL_v2-1.pptx` 和 `1aaf3ec1_示例ppt.pdf` 只提供风格模板。
- 后续模型若把它们当成事实 authority，容易把“示例页逻辑”误写成“本次文献结论”。
## 2.4 literature report 没有单独沉淀成最终母版
- 当前 workspace 中看得到的是：
  - prompt 演化与页面方法论
  - 示例风格件
- 但没有读到单独、稳定、可复用的 literature report 内容母版。
- 因此后续模型做 literature report 时，必须重新回主文献，而不能假定已有现成权威正文。
## 2.5 thesis 机制口径仍有待收束
- `D_thesis_gapmap.md` 和工作文档明确提示：
  - Co(IV) 与 ClO2 证据链尚未完全闭环；
  - Ce 作用口径、XPS/XANES 解释、标准体系锁定仍需统一。
- 因此任何把 thesis 机制链写成“已完全证明”的表达，当前都存在越界风险。
## 2.6 “工作文档”信息量很高，但不等于定稿
- `5c66efd3_【20260305大组会】工作文档.md`
- `99550dc7_【毕业论文】工作文档0305.md`
- 这两份都非常重要，但角色更接近 working memory / 演化仓。
- 后续模型可以用它们理解思路，不应默认其每一处表述都等于最终口径。

## 三、后续写作禁区
## 3.1 禁止把示例 PPT / 示例 PDF 当事实源
- `assets/ppt_pack/1c8b74da_literature_report_FINAL_v2-1.pptx`
- `assets/uploads/1aaf3ec1_示例ppt.pdf`
- 这两份只能学排版、信息密度、每页一结论和讲述逻辑。
- 不能据此直接写：作者结论、图号、实验条件、数据、机制判断。
## 3.2 禁止把 PPT 结论页直接写成 thesis / proposal 定论
- 尤其是：
  - 开题 V3 PPT
  - 大组会最终交付 PPT
  - 任意总结页 / 目录页 / 机制示意页
- 若要写进正式文本，必须回到对应原文页、图页或版本源文件确认。
## 3.3 禁止把中间稿里的强表达直接升级为正式结论
- 例如把：
  - “可能 / 倾向 / 线索 / 待阐明”
  - 直接改写成“证明 / 表明 / 已建立 / 主导路径”
- 特别是在 thesis 的 Co(IV)、ClO2、Ce 调控作用等问题上，必须服从 gap map 与 project 判据。
## 3.4 禁止把模板文件当成内容 authority
- `b807daff_【开题报告】.md` 属于范本约束。
- 它可决定“应该写哪些部分”，不能决定“具体科学内容怎么下结论”。
## 3.5 禁止在未确认版本关系时混写多版本内容
- 同一主题若同时存在：
  - 工作文档
  - markdown 骨架
  - V3 PPT
  - final docx / 最终交付 PPT
- 后续模型必须先标记文件角色，再决定引用口径。
- 不能把不同版本中相互不完全一致的表述直接揉成一个“看似完整”的新版本。
## 3.6 禁止把 working doc 中的 prompt 迭代当成最终写作规则
- `5c66efd3` 中有很多 prompt 与想法演化记录。
- 它们适合抽象成方法，不代表每一条都是最终稳定规范。
- 后续模型引用时应优先抽“原则”，不要逐句继承“临时指令”。
## 3.7 禁止在 thesis 里提前写死未闭环的机制桥接
- 当前尤其不能直接写死：
  - Co(IV) 已被严格证明
  - ClO2 已被完全证实为主导路径
  - Ce 的作用已唯一确定为某一单一路径
  - SMX 结果可无条件外推到“结构多样抗生素”
- 这些都必须等证据链补足后再升级表述。
## 3.8 禁止只根据 PDF/导出稿判断最终版本
- 只要任务涉及继续改正文、改结构、抽主线，就优先寻找：
  - DOCX / PPTX / Markdown 源文件
  - 或 pack 中明确标注的 authority 文件
- PDF/导出稿只适合阅读，不天然等于源文件或最终稿。

## 五、一句话 handoff
- proposal：**正式 authority 是 final docx，revision matrix 负责解释版本关系。**
- thesis：**当前 authority 是主线母版 + gap map，不是单一终稿。**
- group meeting：**最终交付 PPT + replay pack 共同构成最稳 handoff 入口。**
- literature report：**内容 authority 永远是主文献原文；示例 PPT/PDF 只负责风格。**
