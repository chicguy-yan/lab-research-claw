# E_writing_priority
## 1. 优先级
### 1.1 总结论
- **最能测出 pack-quality：组会 pack 复盘**
- **最能测出模型读二进制时的幻觉：thesis reverse engineering**
- **最适合测边界控制/过度桥接：旁支桥接写作**
### 1.2 三类 case 的优先级排序
#### P1｜组会 pack 复盘（主 benchmark）
**推荐原因：**
- 最符合 writing_closure 的核心目标：不是复述材料，而是把材料组织成一个可交付的 pack
- 同时存在“工作文档 → 最终交付 PPT”的真实前件与成品链，适合做 trace replay
- 最容易建立稳定 rubric：可直接检查主线、页面职责、页间承接、结尾收束是否成立
- 幻觉空间相对可控，更适合作为第一批 benchmark 的 baseline
**主测能力：**
- pack 组织能力
- 页面职责设计能力
- 从素材到成品的收束能力
- trace replay / handoff 能力
#### P2｜thesis reverse engineering（高风险 stress case）
**推荐原因：**
- 最容易暴露模型把“待分析 / TODO / 计划补做”写成“已证实结论”的问题
- PPT 文本层标签较多、图像依赖较强、状态混杂，非常适合检测 binary hallucination
- 能测出模型是否真正区分“已做 / 待做 / 已写 / 未写 / 已证明 / 未证明”
**主测能力：**
- 状态分层能力
- 证据边界控制能力
- 读二进制材料时的抗幻觉能力
- 从碎片结果反推 thesis 章节闭环的能力
#### P3｜旁支桥接写作（挑战集）
**推荐原因：**
- 更适合测“会不会乱桥接”，而不是主测 pack-quality 或纯二进制幻觉
- 适合放在第二阶段，用于检验模型是否能区分主线证据与旁支启发
**主测能力：**
- 边界控制
- 可迁移性判断
- 旁支材料与主线材料的桥接克制度
### 1.3 推荐使用方式
- **第一优先上线：**组会 pack 复盘
- **第二优先上线：**thesis reverse engineering
- **第三优先上线：**旁支桥接写作

## 2. pack质量标准
### 2.1 什么叫真正的 pack
**真正的 pack：**围绕一个明确交付对象，把原始材料、组织逻辑、页面职责、证据层级和最终成品收束为一个**可回放、可交接、可判分**的包。
### 2.2 什么只是普通摘要
**普通摘要：**只是把材料内容概括一遍，能说出大意，但没有形成稳定对象、主线、页面功能与回放路径。
### 2.3 pack 与普通摘要的边界
| 维度 | 真正的 pack | 普通摘要 |
|---|---|---|
| 对象 | 明确交付对象、使用场景、受众 | 只是总结内容 |
| 主线 | 有稳定问题链与收束方向 | 只有信息拼接 |
| 页面职责 | 每页知道“要证明什么” | 只有材料堆叠 |
| 证据层级 | 分清草稿/计划/结果/最终稿 | 不区分状态 |
| 生成过程 | 能解释从工作文档到成品如何形成 | 只能复述材料 |
| handoff | 别人接手后能继续改、继续讲、继续评分 | 只能看懂，难以复用 |
### 2.4 pack-quality 的核心判据
#### A. Object clarity｜对象清晰
- 必须能一句话说清：
  - 这是哪类 pack
  - 给谁用
  - 最终交付是什么
- 不能停留在“某资料整理”层面
#### B. Spine clarity｜主线清晰
- 必须存在稳定主线：
  - 问题是什么
  - 为什么这样组织
  - 每个部分在回答什么
  - 最终收束到什么结论上限
#### C. Page function｜页面职责清晰
- 每页都要能回答：
  - 这一页的作用是什么
  - 这一页支撑哪一句话
  - 与上一页和下一页如何承接
- 只有页标题、没有页职责，不算高质量 pack
#### D. State separation｜状态分层清晰
- 必须区分：
  - prompt / 页面要求
  - 工作文档草案
  - 待分析结果
  - 已经完成的结果
  - 最终成品中的结论
- 这是 writing_closure 中最关键的真实性要求之一
#### E. Replayability｜可回放
- 必须能说明：
  - 原始素材是什么
  - 为什么保留这些、舍弃那些
  - 为什么最终形成现在这个结构
- 不能回放生成过程的，只能算顺滑摘要，不算 pack
### 2.5 可直接用于评分的 pack 质量线
- **高质量 pack：**对象清晰、主线稳定、页面职责明确、证据分层真实、生成过程可回放
- **中等 pack：**能看出结构，但页面职责不稳，状态混杂，结论上限模糊
- **普通摘要：**只是概括内容，没有明确交付对象，也无法解释为什么这样组织

## 3. 最容易造假的点
### 3.1 总判断
最容易造假的不是凭空捏造一条完全不存在的结论，而是把**不同状态层的信息混写**：
- 把工作文档里的要求写成已完成事实
- 把 PPT 里的标签词/占位词写成已有完整证据
- 把最终稿里的成熟结论反向投射到前期草稿
- 把 TODO / 待分析 / 本周计划写成已证实结果
### 3.2 三种材料之间最容易混的地方
#### A. 工作文档 → 最终稿
**高危混淆：**把“应该怎么做”的要求，写成“已经这样完成”的事实。
**典型假法：**
- 因为工作文档要求每页都有结论，就说最终稿每页都严格满足
- 因为工作文档规定图文比例、脚注或结构，就默认最终稿已经全部落地
**应判错误：**
- 设计要求冒充完成事实
- prompt/草案冒充真实 trace
#### B. PPT（二进制） → 已证实结论
**高危混淆：**把 PPT 文本层里的主题词、标签词、占位词、待分析提示，写成“图和实验已经支持的结论”。
**典型假法：**
- 看到“Reactive species: ClO2 & Co(IV)=O”就说“已证明体系中同时生成 ClO2 与 Co(IV)=O”
- 看到“XPS+XANES”就说“已充分证明价态重构机制”
- 看到“淬灭/EPR”就说“已完成 ROS 归属与贡献判定”
**应判错误：**
- 二进制文本层脑补
- 页标题冒充页结论
- 图像不可见时擅自补足图意
#### C. 最终稿 → 前期材料
**高危混淆：**把最终交付中的成熟表达，反向覆盖工作文档或 thesis 草稿，使整个过程看起来从一开始就已经闭环。
**典型假法：**
- 用 final 里的结论语言替前期材料补全因果链
- 默认前期草稿已经达到 final 同等级的成熟度
- 用最终收束好的主线去抹平真实的迭代、犹豫和未定稿痕迹
**应判错误：**
- 时序倒置
- final wording 反投射
- 过程真实性丢失
### 3.3 thesis reverse engineering 中最危险的造假点
- 把 `TODO` 当成已完成实验
- 把 `待分析` 当成已确认结论
- 把“需要补图/增加图”当成已有证据
- 把“暂时解释不上去”的机理，写成已得到合理闭环
- 把“计划这周做”的实验，写成 thesis 中已可使用的证据页
### 3.4 一组应重点拦截的红旗词
以下词出现时，结论强度必须自动下调，否则容易造假：
- `TODO`
- `待分析`
- `待核对`
- `增加图`
- `需要补充`
- `暂时`
- `这周做`
- `看看可不可以`
- `后续补`
- `计划`
### 3.5 benchmark 应重点判罚的错误类型
| 错误类型 | 表现 | 严重程度 |
|---|---|---|
| 状态混淆 | 把计划/草稿/待分析写成完成态 | 高 |
| 二进制脑补 | 根据 PPT 标签词擅自补足图意与结论 | 高 |
| final 反投射 | 用最终稿语言覆盖前期材料 | 高 |
| 旁支越界 | 把启发性材料写成主线证据 | 中高 |
| 普通摘要冒充 pack | 只会总结内容，不能回放组织过程 | 中 |

## 4. 结论摘要
- 若只先做 writing_closure benchmark，**首选 case 应是“组会 pack 复盘”**，因为它最能稳定测出 pack-quality
- 若想重点抓模型读 PPT / 二进制材料时的幻觉，**首选 case 应是“thesis reverse engineering”**
- 若想测模型会不会把旁支材料硬桥到主线，**再补“旁支桥接写作”作为挑战集**
- 评分时必须把“pack 质量”与“状态真实性”分开；否则会奖励把草稿自动写顺的幻觉型模型
