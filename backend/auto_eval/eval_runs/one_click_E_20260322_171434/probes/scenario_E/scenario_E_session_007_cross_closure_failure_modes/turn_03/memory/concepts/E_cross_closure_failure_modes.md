# E_cross_closure_failure_modes
> 目的：把当前 workspace 中“文献线 -> 实验线 -> 写作线”的高频断链点、误迁移模式与防呆规则收束成一个可复用概念文件，供后续 bridge/eval、prompt contract 与 hallucination 指标设计复用。
>
> 适用对象：Ce-Co3O4 / NaClO2 体系下的高价钴、ClO2、选择性氧化与毕业论文组织。
>
> 判据基线：机理论断需服从 `memory/identity/project.md` 中的 Claim -> Evidence 规则，尤其是：
> - `ClO2` 不能只靠单次显色/气味/颜色变化下结论；
> - `Co(IV)` 不能只靠单个间接证据下结论；
> - 探针、谱学、淬灭、同位素、动力学必须标注证据等级与空白/对照完备性。

## 2.2 高风险触发词
以下词一旦出现在 source 中，默认不应被改写成“已完成/已证实/我们观察到”：
- 计划词：`TODO`、`目标`、`先`、`再`、`优先做`、`准备`、`需要补充`、`看看可不可以`
- 草稿词：`图源`、`主结构参考`、`结论：`、`初步大纲`、`重新规划`
- 引用词：`基于 Su 等（2024）`、`参考文献`、`这篇文献`、`原文图3E/F/G`
- 修辞词：`改口`、`先不再说`、`改说`、`暂时拔高不了`
- 采购/SOP 词：`CAS`、`商家`、`配置`、`棕色瓶`、`避光保存`、`一周内用完`
## 2.3 适合 eval 的五类误迁移方向
1. `literature -> our_result`
2. `method_reference -> observed_evidence`
3. `plan/TODO -> completed_experiment`
4. `writing_draft -> stable_conclusion`
5. `supporting_evidence -> direct_proof`

# 三、防呆规则
## 3.1 source type 防呆
每段材料在进入模型前，至少标一类：
- `literature_note`
- `method_reference`
- `task_plan`
- `writing_draft`
- `result_note`
- `procurement_or_SOP`
- `conflict_pending`
**规则**：未标 `result_note` 的段落，默认不得输出为“已完成结果”。
## 3.2 时态防呆
若 source 中出现以下词：
`要 / 先 / 再 / TODO / 目标 / 需要补充 / 可以这周做 / 看可不可以`
则输出层禁止自动升级为：
`已完成 / 已观察到 / 已证明 / 已建立 / 已获得`
## 3.3 归属防呆
若 source 中出现：
`图源 / 参考文献 / 基于XX研究 / 原文 / SI / figure`
输出必须保留归属前缀，例如：
- “文献启发显示……”
- “外体系参考表明……”
- “该方法在文献中可行，但我方尚未完成验证……”
禁止改写为：
- “本研究显示……”
- “我们证明了……”
## 3.4 证据等级防呆
对 `Co(IV)` 与 `ClO2` 相关结论，强制使用以下四级标签：
- `A = 直接证据组合充分`
- `B = 强支持，但仍属间接`
- `C = 初步支持/方法学可行`
- `D = 仅文献启发或计划项`
默认输出规则：
- `A/B` 才允许写“支持存在/支持参与”；
- `C` 只能写“提示/倾向于”；
- `D` 只能写“文献启发/待验证/计划进行”。
## 3.5 冲突防呆
若同一对象出现相反表述，例如：
- XANES 一处写“右移升价”，另一处又写“目前 XPS 和 XANES 都是降低价态”；
则输出必须显式写：
- “当前判读存在冲突，尚未统一。”
- “此处只能保留为 pending interpretation。”
禁止模型自动择一站队。
## 3.6 图-论断锚定防呆
每张主图必须回答三个问题：
1. 这张图唯一主 claim 是什么？
2. 这张图对应的样品矩阵是否固定？
3. 这张图属于：结果图 / 模板图 / 参考图 / 计划图？
若第 3 问不是“结果图”，则正文中不得写成实验结论。
## 3.7 样品命名防呆
所有输出必须映射到统一样品注册表：
- 正式名
- 简写
- 掺杂量
- 合成条件
- 历史别名
- 图例名
**规则**：同一样品若出现多个名称但未完成映射，禁止做跨图比较或跨章节汇总。
## 3.8 章节意图 vs 已得结果 防呆
出现如下句式时：
- “第一章要证明……”
- “第二章看情况……”
- “以 SMX 为主去思考……”
一律判定为：`chapter_intent`
**规则**：`chapter_intent` 不能在摘要、结论、答辩口径中改写为 `chapter_achieved_result`。
## 3.9 eval 指标建议
适合后续 benchmark / hallucination 检测的指标：
- `Source Type Confusion Rate`：把非结果 source 误说成结果的比例
- `Tense Upgrade Rate`：把计划时升级为完成时的比例
- `Attribution Drop Rate`：丢失文献/图源归属的比例
- `Evidence Inflation Rate`：把支持证据抬升为直接证明的比例
- `Conflict Suppression Rate`：存在冲突时仍输出单向确定结论的比例

# 五、可直接复用的最小工作原则
1. 先问：这句话来自文献、计划、草稿，还是结果？
2. 再问：这句话的证据等级是 A/B/C/D 哪一级？
3. 最后问：这句话是否跨越了 source type 边界？
如果以上任一问题答不清，就不能写成稳定结果。
