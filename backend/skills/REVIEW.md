# Review · mechanism_mapping

## 1. 这个 skill 是否只解决一件高频、可复用的事？
是。
它只解决“机理分析图谱搭建”这一件事，不负责证据链聚合、谱图细读或汇报排版。

## 2. 名称是否是动作/流程，而不是科研结论？
是。
`mechanism_mapping` 是方法名，不绑定任何具体体系或结论。

## 3. 输入是否明确？
是。
最低输入是机理问题 + 文献/表征/实验现象中的任意组合。
增强输入包括图号、候选解释、已有草稿等。

## 4. 输出是否明确？
是。
输出包含机理问题、分支图谱、映射链、证据状态、未解决问题和验证建议。

## 5. 是否写清楚了证据不足时的处理方式？
是。
本 skill 明确要求区分直接证据、间接证据、类比支持、推断和待验证内容。

## 6. 是否写清楚了边界和禁止事项？
是。
已明确不用于单篇总结、单图描述、路径比较、图谱联合判读和排版润色。

## 7. 是否能迁移到别的 workspace，而不是写死当前课题？
是。
core 不含具体课题名、路径名、用户记忆或文件目录。

## 8. 是否已经在一个真实闭环样例中被调用并通过？
待验证。
当前已完成 core + example + eval + binding 设计，下一步需在真实机理闭环样例中回归测试。

## Overall Verdict
可进入第一轮真实闭环测试。
当前风险不在 core，而在：
- 是否会与 `mechanism_evidence_chain` 边界重叠
- 是否会在输入过少时过度生成分支
- 是否会把“合理推断”写成“事实主线”
