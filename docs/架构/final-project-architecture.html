Experimental-Research-OpenClaw Final Project Architecture

这份页面只依据当前代码生成，范围覆盖 backend/ 与 frontend/index.html。 它描述的是现在真实可运行的系统，不引用已经过时的 phase 文档，不把计划态模块写成已实现。

15 HTTP 端点。包含健康检查、会话 CRUD、文件系统、Agent 目录、附件上传与下载。
5 已注册给 LangChain Agent 的工具：terminal、python_repl、read_file、write_file、fetch_url。
1 实际前端入口：frontend/index.html。当前不是 Next.js，多数交互靠原生 DOM + fetch + SSE reader。
default 运行时 workspace 锚定在 .openclaw/workspace-default。可创建别的 workspace，但当前流程不会切换过去。
当前最重要的真实边界

/api/agents 已能创建和列出多个 workspace，但 SessionManager 与 AgentManager 在启动时都绑定到 DEFAULT_WORKSPACE_DIR，前端也没有 Agent 选择器。 所以现在的系统本质上是“单运行时 workspace + 可额外建目录”的架构。

1. System Overview

当前系统由一个静态研究控制台、一个 FastAPI 后端、一个基于本地文件系统的 workspace、以及一个按请求重建的 LangChain Agent 组成。 “记忆层、技能菜单、工具审计、附件溯源” 已经在代码里串成一个闭环。

Frontend

Research Console

三栏工作台已经落在单文件 HTML 中：

  • 左栏：Workspace Memory 与 Skills 文件树
  • 中栏：聊天流、SSE 工具事件、Trace 查看器、附件上传
  • 右栏：Concepts / Tasks / Packs 原子笔记树
  • 会话切换、后端地址探测、移动端抽屉逻辑都在前端 JS 中完成
Backend

FastAPI Runtime

后端只暴露已实现能力，不存在 traces/tokens/config 独立路由：

  • app.py 在启动时初始化 workspace、SessionManager、AgentManager
  • 聊天接口通过 SSE 持续返回 token / tool_start / tool_end / done
  • 文件、会话、Agent 目录、附件上传下载均已可用
Agent Layer

Prompt + Tools + Audit

单轮对话真实链路如下：

  • ContextOrchestrator 生成 Memory Map 与推荐文件
  • SkillLoader 生成技能菜单快照并同步 system skills 到 workspace
  • PromptBuilder 拼出完整 system prompt
  • AgentManager 基于 create_agent 临时构建 Agent 并执行 5 个工具
  • TraceWriter 把工具调用和 prompt 写回 envelope
Storage

Workspace as Database

项目当前没有外部数据库，核心状态都落到 workspace 文件系统：

  • context_trace/{session_id}.json 保存消息、trace、prompt
  • memory/ 保存 L1/L2/L3 研究记忆
  • assets/ 保存上传附件并自动分类
  • skills/ 保存 registry、snapshot 与镜像后的 system skills

2. End-to-End Request Flow

下面的链路只描述当前代码里真实存在的执行步骤。Trace 面板没有独立 API，而是由前端直接读取 context_trace/{session_id}.json。

Step 1

Browser Console

用户在 frontend/index.html 中选择会话、可选上传附件、输入消息。 route 与额外 prompt_context 取自 URL hash。

Step 2

POST /api/chat

后端确保 session 存在，随后创建 ContextOrchestrator、SkillLoader、PromptBuilder， 组装本轮 prompt payload。

Step 3

Agent Execution

AgentManager 调用 langchain.agents.create_agent，注册 5 个工具， 并把模型流式输出翻译成标准 SSE 事件。

Step 4

Persistence

api/chat.py 在流结束后写入 user/assistant 消息； TraceWriter 把 tool_calls 与 prompt 写进 session envelope。

Step 5

Frontend Trace Readback

前端收到 done 后，重新读取 /api/files?path=context_trace/{session_id}.json， 展示审计摘要与完整 Trace 面板。

SSE Events

流式事件协议

当前前端显式处理 token、tool_start、tool_end、 new_response、error、done 六类事件。

Trace Access

没有独立 Trace API

Trace 回放不是走 /api/traces，而是借用 /api/files 直接读取 JSON 文件。 这意味着“文件 API”同时承担了回放接口职责。

4. API Surface

下表只列当前代码里真的注册到 FastAPI 的端点。没有把未实现的 phase 计划接口算进去。

Method Path Current Role Notes From Code
GET / 健康检查 返回 status 与服务名，前端会拿它探测后端地址。
POST /api/chat SSE 流式对话 请求体包含 message、session_id、route、prompt_context、attachments。
GET /api/sessions 会话列表 按 updated_at 倒序返回。
POST /api/sessions 创建会话 创建 12 位十六进制 session id。
PUT /api/sessions/{session_id} 重命名会话 只更新 index，不动 envelope 内容。
DELETE /api/sessions/{session_id} 删除会话 删除 context_trace/{session_id}.json 并更新索引。
GET /api/sessions/{session_id}/history 读取消息历史 返回原始 messages 数组，不包含 trace。
GET /api/files?path=... 读取文本文件 前端也借这个端点读取 context_trace JSON。
POST /api/files 保存文本文件 受 resolve_safe_path(..., require_writable=True) 限制。
GET /api/files/tree 目录树 会隐藏 dotfiles，且隐藏大多数下划线目录，但保留 skills/_system。
GET /api/files/preview 文本预览 当前前端主流程没有显式使用它。
GET /api/agents 列出 workspace 从 .openclaw/workspace-* 读取元信息。
POST /api/agents 创建 workspace 复制 workspace-templates 并写入 IDENTITY.md。
POST /api/assets/upload 上传附件 支持自动分类、SHA8 文件名前缀、轻量摘要。
GET /api/assets/download 下载或预览二进制附件 只允许读取 assets/ 下的文件。

6. Tooling and Data Contracts

工具层已经是这个项目的核心能力，不只是补充。它决定了 Agent 能否真正改文件、读记忆、跑实验脚本、抓网页。

Tool File Current Contract Guardrail
terminal backend/tools/terminal_tool.py 参数是 command + cwd + timeout 黑名单、workspace cwd 限制、300 秒以内、输出 10000 字截断
python_repl backend/tools/python_repl_tool.py 执行任意 Python 代码，workspace 自动注入 sys.path cwd 必须在 workspace 内，异常转字符串返回
read_file backend/tools/read_file_tool.py 按 path + cwd 读取文本 路径安全、UTF-8 优先、GBK 回退、20000 字截断
write_file backend/tools/write_file_tool.py 写文本，支持 source_assets 只允许写可写前缀；写入 memory/ 时会自动注入溯源 frontmatter
fetch_url backend/tools/fetch_url_tool.py 拉取 HTTP(S) 网页并转 Markdown 仅允许 http/https，10 秒超时，html2text 转换，20000 字截断

7. Current Constraints and Architectural Truths

这些不是建议，而是当前代码表现出来的事实。新页面必须把它们写清楚，否则后续开发很容易在错误假设上继续堆功能。

Workspace Truth

多目录，不是多运行时

尽管可以通过 /api/agents 创建多个 workspace-{agent_id}，但 app 启动后只把默认 workspace 注入到 app state。聊天、文件、附件都仍然操作 default workspace。

Trace Truth

会话文件与审计文件合并

当前 session 历史、tool traces、prompt payload 都保存在同一个 envelope JSON 中，而不是拆成多份存储。

Frontend Truth

路由上下文来自 URL hash

route 和其他 prompt metadata 不是靠表单，而是由前端从 location.hash 提取后注入请求体。

Attachment Truth

附件已进入主链路

附件上传结果会成为 ChatRequest.attachments，既进入 metadata，也会在保存 user message 前被拼接进消息文本。

Skill Truth

SkillLoader 只做披露，不做匹配

技能决定权仍在 Agent 本身。后端没有做 trigger 命中、route 排序或自动读取完整 SKILL.md。

UI Truth

Trace 回放依赖文件接口

前端通过 /api/files 读取 envelope，再自己提取 traces。这会让文件 API 成为审计展示的隐式依赖。

8. Security and Boundary Controls

当前安全边界主要体现在路径解析、shell 工具限制、资产下载目录限制，以及 memory 文件的来源追踪。

Path Safety

relative_to() 是主边界

graph/path_utils.py 用 Path.relative_to() 做 workspace 越界检查，避免了字符串前缀误判。可写目录白名单只有 memory/、assets/、context_trace/、skills/。

Terminal Safety

Shell 能跑，但不是无限制

terminal_tool.py 限制 cwd 在 workspace 内，带命令黑名单、超时、输出截断。它仍然很强，因此它是整个 runtime 的关键风险点之一。

Asset Safety

下载仅开放 assets/

/api/assets/download 会在路径解析后再次验证相对路径前缀必须是 assets/，不允许借下载端点读取 memory 或 trace。

Traceability

知识文件可追溯回附件

当 Agent 用 write_file 往 memory/ 写入内容且附带 source_assets 时，工具会自动注入 frontmatter，确保研究结论可以追溯到原始资产。
