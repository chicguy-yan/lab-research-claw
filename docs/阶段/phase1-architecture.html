3. 核心模块职责

app.py Phase 1
backend/app.py
FastAPI 入口。启动时：① 从 workspace-templates 初始化 workspace-default ② 创建 SessionManager + AgentManager ③ 注册 API 路由
ensure_default_workspace() → shutil.copytree
on_startup() → 初始化所有 Manager
config.py Phase 1
backend/config.py
全局配置。读取 .env 环境变量，定义路径常量（BASE_DIR / OPENCLAW_DIR / WORKSPACE_TEMPLATES_DIR），提供 config.json 读写
load_config() → dict (rag_mode 等)
save_config(config) → config.json
AgentManager Phase 1
backend/graph/agent.py
LangChain Agent 构建与流式调用。使用 create_agent()（LangGraph runtime），每次请求重建以确保 workspace 编辑即时生效
initialize() → 创建 ChatOpenAI
_build_agent(system_prompt) → CompiledStateGraph
astream(msg, history, prompt) → yield SSE events
SessionManager Phase 1
backend/graph/session_manager.py
JSON 会话持久化。消息存储在 context_trace/{session_id}.json（envelope schema: {"messages": [...], "traces": []}），元数据存储在 _sessions_index.json
create_session(title) → Session
list_sessions() → sorted by updated_at
load_session_for_agent(id) → 合并连续 assistant
save_message(id, role, content) → 追加消息
rename_session / delete_session
chat.py (API) Phase 1
backend/api/chat.py
POST /api/chat — SSE 流式对话端点。加载历史 → 流式调用 Agent → 持久化消息 → 统一发送 done 事件
chat(body: ChatRequest) → StreamingResponse
sessions.py (API) Phase 1
backend/api/sessions.py
会话管理 5 个端点：list / create / rename / delete / history。所有操作通过 SessionManager 完成
GET /api/sessions → 列表
POST /api/sessions → 创建
PUT /api/sessions/{id} → 重命名
DELETE /api/sessions/{id} → 删除
GET /api/sessions/{id}/history → 历史

5. SSE 事件序列

普通模式（Phase 1）

event: token × N
data: {"content": "..."}
逐 token 推送文字内容
event: done × 1
data: {"session_id": "..."}
流结束 + 消息已持久化

带工具调用（Phase 4+）

event: token × N
event: tool_start
data: {"tool": "...", "input": "..."}
event: tool_end
data: {"tool": "...", "output": "..."}
event: new_response
工具调用后的新 assistant 气泡
event: token × N
event: done × 1

7. 关键决策记录

Bug Fix：stream_mode + node_name 修正
原代码使用 stream_mode="updates" + node_name == "agent"，但 create_agent 返回的节点名为 "model"，且 updates 模式不支持逐 token 流式。
修正为 stream_mode="messages"，返回 (AIMessageChunk, metadata) 元组，实现真正的逐 token SSE。
决策：done 事件归属
AgentManager 只产出 token / tool_start / tool_end / new_response / error。
done 由 api/chat.py 在 Agent 流结束 + 消息落盘后统一发送，避免重复。
决策：Session 消息 vs 元数据分离
context_trace/{session_id}.json = envelope schema {"messages": [...], "traces": []}（Step 10 修正，兼容旧版纯数组格式）。
context_trace/_sessions_index.json = 会话元数据（title / created_at / updated_at）。
注意：依赖版本兼容性
LangChain v1.1.3 的 create_agent 节点名为 "model"（非 "agent"）。
若未来版本改名，需同步更新 graph/agent.py 中的判断逻辑。
