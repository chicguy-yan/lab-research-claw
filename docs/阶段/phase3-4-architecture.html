6. 关键决策记录

决策 1: 保留简化版 ContextOrchestrator
理由：需要生成 Memory Map（目录结构）和基于关键词推荐文件，但不预先注入文件内容，保持灵活性。LLM 通过 read_file 工具主动访问 memory。
决策 2: 5 个核心工具（包含网络访问能力）
理由：JSON 用户示例中大量数据分析场景，PRD 明确要求核心工具。fetch_url 提供基础的网络信息获取能力，支持研究场景。这是最小 MVP 的必要能力。
决策 3: 明确 Assets 溯源机制
理由：用户明确要求"memory 文件带 assets 路径"，便于用户溯源和审计，支持多模态（CSV/图片/PDF）。通过 PromptBuilder 注入溯源规则到 System Prompt。
决策 4: Phase 3 不处理 skills，完全由 Phase 5 负责
理由：职责分离（Phase 3 负责静态控制层，Phase 5 负责动态技能加载）+ 按需加载（避免每次都注入所有 8 个技能，节省上下文）+ 可扩展性（未来可以实现更复杂的技能匹配逻辑）。
决策 5: Layer 2 必须包含 stage_reports/
理由：阶段汇报是重要的交付物（组会 PPT、阶段总结），模板明确定义了 memory/timeline/stage_reports/ 路径，与 AGENTS.md 的规范保持一致。
