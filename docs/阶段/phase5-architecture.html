6. 关键决策记录

决策 1: Agent 自主决策，后端不做匹配
删除后端 match_skills 逻辑，Agent 通过 read_file 自主读取技能。理由：Agent 可根据对话上下文做更智能的判断；架构更清晰（后端只提供菜单 + 文件准备）；通过 TraceWriter 记录实际读取了哪些技能，比后端匹配更透明。
决策 2: 渐进式披露——snapshot 常驻，完整内容按需
每轮注入 SKILLS_SNAPSHOT.md 菜单摘要（~1.7KB）；Agent 通过 read_file 按需读取完整 SKILL.md。snapshot 体积小不影响上下文预算；完整 SKILL.md 按需加载节省 token；Agent 能感知有哪些技能而不被全量内容淹没。
决策 3: route 是工作语境，不是匹配条件
route 用于 context selection、atom_decision、trace，不用于技能匹配。preferred_routes 只是描述信息供 Agent 参考，backend 不得基于此做过滤、排序、自动选择。当前通过 URL hash 传入（#route=mechanism_closure），Phase 6 可添加 UI 选择器。
决策 4: 复制和写盘策略——克制
SKILL.md 复制到 workspace：只在不存在时复制，不覆盖用户定制版本。SKILLS_SNAPSHOT.md 写盘：只在首次不存在时写盘，不每轮强制写入。目的：尊重用户定制、减少 I/O 开销。
决策 5: entry 路径约定不变，代码侧适配
registry.json 中 entry 格式为 "skills/xxx/SKILL.md"（相对于 backend/），与旧版保持一致。SkillLoader 中使用 SKILLS_DIR.parent / entry 拼接实际路径，避免双重前缀问题。
