5. 请求流程：附件上传 → Agent 解析 → 溯源写入

用户拖拽/选择文件 → 前端 pendingFiles[]
    │
    ▼ 点击发送

    ▼
后端 assets.py
    ├─ SHA256 → sha8 前缀
    ├─ AUTO_CLASSIFY → 目标子目录
    ├─ 写入 assets/{dir}/{sha8}_{name}
    ├─ _quick_summary() → 轻量摘要
    └─ 返回 {saved_path, sha256, file_type, quick_summary, ...}
    │
    ▼
前端构建 attachments[]
    │ POST /api/chat {message, attachments, ...}
    ▼
后端 chat.py
    ├─ attachments → metadata.attachments
    ├─ user_msg 前拼接 "[附件已上传]\n- path (type, summary)"
    ├─ PromptBuilder.build(metadata=...) → system prompt 含附件清单
    └─ Agent 流式执行
         │
         ├─ Agent 读 skills/pdf/SKILL.md
         ├─ Agent 用 python_repl 调 pypdf 解析 PDF
         ├─ Agent 调 write_file(path, content, source_assets=[...])
         │       │
         │       └─ WriteFileTool._inject_source_assets_frontmatter()
         │          → 自动注入 YAML frontmatter 到 memory/ 文件
         └─ 返回结果

6. 关键决策记录

决策 1：深度解析交给 Agent，不建 parsers/ 层

官方 skill（pdf/docx/pptx）是给 Agent 看的指令文档。Agent 已有 python_repl + terminal，读完 SKILL.md 后自己就能解析。后端只做 quick_summary，不重复实现 Agent 已有的能力。减少 8 个新文件和 7 个新依赖。

决策 2：source_assets 在工具层强制注入

不依赖 Agent 手动写 frontmatter（不可靠）。WriteFileTool 自动注入，只要 Agent 传了 source_assets 参数就生效。仅对 memory/ 路径生效。

决策 3：SHA8 命名去重

落盘路径 {sha256前8位}_{filename}。同内容同名 = 同路径（幂等），不同内容同名 = 不同路径（不覆盖）。保护溯源稳定性。
