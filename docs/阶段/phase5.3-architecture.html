4. 核心模块职责

WorkspaceRuntimeRegistry
中央注册表。管理 workspace 生命周期（provision/bootstrap/active）、manifest CRUD、runtime 懒加载。启动时初始化共享资源，按需创建 per-workspace runtime。
SharedAgentResources
进程级单例。持有共享 ChatOpenAI 实例和 FetchURLTool。所有 workspace 共用同一个 LLM 连接。
WorkspaceRuntime
per-workspace 隔离单元。持有该 workspace 的 SessionManager 和 workspace-scoped tools（Terminal/PythonREPL/ReadFile/WriteFile）。
runtime_context.py
API 层统一入口。从 X-Workspace-Id header 或 body 解析 workspace_id，返回对应 WorkspaceRuntime。所有 API 共用。
workspaces.py
Workspace CRUD API。provision（POST）、rename（PUT）、list（GET）、manifest 读取、bootstrap/start 状态流转。
chat.py (Phase 5.3)
不再依赖全局 AgentManager。每请求用 shared.llm + workspace tools + system_prompt 临时构建 agent，直接 astream。
workspace_manifest.json
机器可读元数据。workspace_id、display_name、description、bootstrap_status（pending/running/completed/failed）、timestamps。
BOOTSTRAP.md (v1.0)
Agent 可读的 first-run 初始化协议。定义 scope discovery → asset intake → generation plan → identity generation → handoff 全流程。由 bootstrap runner 触发执行。

6. 关键决策记录

决策 1：请求级 workspace 选择，不做全局切换
不新增 POST /api/agents/switch 或 app.state.current_workspace。每个请求通过 X-Workspace-Id header 显式指定 workspace，并发安全。
决策 2：共享 LLM，隔离 tools
ChatOpenAI 和 FetchURLTool 是无状态的，进程级共享。TerminalTool/ReadFileTool/WriteFileTool/PythonREPLTool 依赖 workspace_dir，按 workspace 隔离。
决策 3：manifest 由 runner 写，不由 agent 写
workspace_manifest.json 是系统级状态文件。bootstrap_status 的流转由 bootstrap runner（后端代码）负责，不由 BOOTSTRAP agent 通过 write_file 工具直接回写。
决策 4：provision ≠ bootstrap
POST /api/workspaces 只做 provision（创建目录 + 写 manifest + pending）。bootstrap 是独立的后续步骤，通过显式 start 入口触发。
决策 5：display_name 在 manifest，不在 IDENTITY.md
workspace 命名元数据由 workspace_manifest.json 承担。IDENTITY.md 和 project.md 只写 agent 可读的语义内容。
