5. 路径安全防护（PRD §6.9）

高风险项已解决：resolve_safe_path() 三层防护，写操作额外白名单检查
1
禁止 .. 分量 — 检测路径中的 ..，直接拒绝。防止 ../../etc/passwd 类攻击
2
符号链接解析 — Path.resolve() 解析所有符号链接后，检查最终路径仍在 base_dir 内
3
写入白名单 — require_writable=True 时，检查路径前缀是否在 WRITABLE_PREFIXES 内（memory/, assets/, context_trace/）

GET /api/files/tree — 目录树

curl GET

curl POST
/api/files → files.py → resolve_safe_path()
(写模式 + 白名单) → mkdir -p
父目录 → write_text()

POST /api/agents — 创建 Agent

curl POST
/api/agents → agents.py → 检查 agent_id
正则 + 长度 → 检查不存在
(409 if exists) → copytree()
workspace-templates → 写入
IDENTITY.md

7. 目录树过滤规则

过滤策略

_build_tree() 跳过以 . 或 _ 开头的文件/目录
规则效果
. 前缀隐藏 .env, .openclaw 等配置文件
_ 前缀隐藏 _sessions_index.json 等内部文件
目录优先排序目录在同级文件前面显示
深度限制 1-10默认 3 层，防止过深递归

返回格式示例

// GET /api/files/tree?path=memory/&max_depth=2
{

      ]
    },

  ┌──────────────────────┐
  │  workspace-templates │   模板源（不可变）

  │   + assets + trace)  │

name 最长 128 字符，POST 创建时写入 IDENTITY.md（# {name}）。列举时优先从 Name（名字）： 字段提取，回退到非模板标题行

10. 关键决策记录

路径安全：三层防护（PRD §6.9）
resolve_safe_path(base, path, require_writable) — 禁止 .. → 解析符号链接 → 边界检查 → 白名单
写入仅允许：memory/, assets/, context_trace/
决策：Workspace 定位
Files API 通过 request.app.state.session_manager._workspace_dir 获取当前 workspace 根目录。
Phase 2 固定 workspace-default，Phase 6 支持 Agent 切换后动态变更。
决策：目录树过滤
隐藏 . 和 _ 开头的文件/目录（避免暴露内部文件）。
目录优先排序，默认深度 3 层。
补全：assets/uploads/ 缺失项
Phase 1 对齐检查发现 PRD §4.8.3 要求的目录缺失，Phase 2 补充 workspace-templates/assets/uploads/README.md。
