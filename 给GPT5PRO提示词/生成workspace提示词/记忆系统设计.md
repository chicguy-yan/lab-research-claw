# Researchloop-OpenClaw 记忆系统 README

> 目标：把 180 天实验周期跑成“可追溯、可验证、可回放、可沉淀”的工作台。
> 分三层：**Layer1 身份与规则**（长期稳定）、**Layer2 时间轴推进**（阶段到每天）、**Layer3 原子笔记资产**（跨周期证据链与可复用对象）。

---

## 0. 设计原则

* **File-first Memory**：所有记忆以 Markdown/JSON 落盘，任何时刻可用 Obsidian/VS Code 打开检视。
* **透明可控**：每回合把“读了哪些文件、写了哪些文件、缺哪些字段”写入回放 trace。
* **最小但硬**：对象字段少而必要，强制证据锚点与数据路径，减少“凭印象写结论”。


阶段性推进（每隔一段时间就要做组会/PPT、复盘卡点、列下一步计划）
你在周期中多次出现“第 N 次阶段汇报”的请求，且会带素材打包路径（如 assets/ppt_pack/R06_20251123，后面还有 R09/R10 等）。

实验闭环压力（今天做了什么，是否能支撑主线，要补什么对照/表征）
典型就是：合成 checklist、参数矩阵、以及“这组 XRD/SEM/XPS 能证明什么不能证明什么”。

机理证据链压力（你反复强调要补齐 Co(IV) / ClO₂ 的“硬证据链”）
你反复在 Close/机理环节追问 “PMSO探针 + DPD显色 + 淬灭剂 + 必要空白/对照” 的组合与判据。

写作结构压力（Results & Discussion 目录树 + 每节中心句 + 主文/SI放图策略）
你多次要“章节逻辑”树形目录，并且强调“每节要证明什么”。

所以你的记忆系统必须能同时做到：

粗粒度：阶段里程碑、主线假设、当前最大不确定性、下一步验证计划

细粒度：每天实验 SOP、编号/污染风险提醒、数据路径、拟合结果、图表产物

跨周期：可追溯的 Claim-evidence、可复用的 Protocol、可累计的 RunResult 反向索引

可沉淀：高重复的交付（比如“按时间顺序 checklist”、“阶段汇报PPT提示词”）自动提炼成 Skill

## 1) Layer1：Identity（身份与规则层）

**一句话**：让系统长期知道“你是谁、项目是什么、输出该长什么样”。

### 1.1 目录

```text
memory/identity/
  user.md                # 用户偏好与输出约束
  project.md             # 项目主线假设、指标、术语表
  lab_context.md         # 实验室现实约束：仪器、可做表征、命名规则
  context_budget.md      # 可选：单回合最多读多少文件/摘要策略
```

### 1.2 核心内容建议

* `user.md`：你明确的风格偏好（少噪声、why/what 优先、需要给出缺口而非脑补）、常用输出结构（表格/清单/模板）。
* `project.md`：主线假设、关键指标（kobs、选择性、副产物）、关键术语（ClO₂/Co(IV)/OAT/PCET 等）与“哪些证据才算支持/不支持”的判据。
* `lab_context.md`：设备可用性、常见误差源（显色干扰、淬灭剂副反应）、样品编号规范。

## 2) Layer2：Timeline（时间轴推进层）

**一句话**：把 180 天从“阶段计划”落到“每天执行”，并自动汇总为阶段汇报 Pack。

### 2.1 目录

```text
memory/timeline/
  180d_index.md                 # 180天总览：阶段划分、里程碑、风险雷达
  phases/
    P01_bootstrap.md
    P02_material_screening.md
    P03_parameter_optimization.md
    P04_mechanism_closure.md
    P05_writing_submission.md
  weeks/
    2025-W39.md
    ...
  days/
    2025-12-31.md
    ...
  stage_reports/
    R09_20260119.md
    ...
```

### 2.2 Day / Stage 的最小字段（建议）

* `days/YYYY-MM-DD.md`

  * `today_goal`
  * `concept_focus`
  * `planned_tasks[]`
  * `decisions[]`
  * `artifacts_generated[]`（图、表、数据包路径）
  * `open_questions[]`
* `stage_reports/Rxx_*.md`

  * `time_range`
  * `topline_story`
  * `key_results` / `blockers` / `debug_actions` / `next_plan`
  * `assets_pack`（ppt_pack 路径）
  * `open_questions_to_PI`

## 3) Layer3：Atom Notes（原子笔记资产层）


### A. 简洁版（你最新提出的“原子笔记”）

* **Concept**：主题容器（你在验证什么）
* **Task**：一次验证任务（= Claim + Protocol + Run）
* **Pack**：把证据链写成最终交付物（组会/机理/写作/图集）

#### 3.1 目录

```text
memory/concepts/
  CONCEPT_*.md
memory/tasks/
  TASK_*.md              # 内含 Claim + Protocol + Run（可追加多次 run）
memory/packs/
  PACK_*.md              # stage_report/mechanism/writing/figure 等交付包
```

#### 3.2 对象最小字段（建议）

* `Concept`

  * `id, name, scope, keywords`
  * `north_star`（一句话主线）
  * `active_tasks[]`
* `Task`（Claim + Protocol + Run）

  * Claim：`claim_text` + `evidence`（缺 evidence 禁止入库）
  * Protocol：`steps[]`（带 checkpoint）+ `controls[]`
  * Run：`raw_data_paths[]` + `quick_results` + `verdict`
* `Pack`

  * `pack_type`：`mechanism_pack | stage_report_pack | figure_pack | writing_pack`
  * `task_refs[]`
  * `final_assets[]`（ppt_pack、png、段落等）
  * `takeaways[]`（每张图/每条证据一句话结论）

## 4) OpenClaw 工作台回放：Context Trace

**一句话**：每回合都能点一下回看“读/写/缺/用到的技能与工具”。

### 4.1 目录

```text
.openclaw/context_trace/
  T0001.json
  T0002.json
  ...
```

## 5) 运行时的 Context 拼接顺序（推荐默认）

每次回答默认按“稳定 → 变化 → 本轮输入”拼接：

1. `memory/identity/user.md`
2. `memory/identity/project.md`
3. `memory/timeline/180d_index.md` + 当前 `phase.md`
4. 若是“最近/今天”：对应 `days/YYYY-MM-DD.md`
5. 当前 `CONCEPT` + 相关 `TASK`/`PACK`
6. `skills/`（可选：只读 registry + 本次选中的 skill）
7. 本轮用户输入 + uploads

> 缺字段就写进 `missing[]` 并触发追问，避免系统“编”。

---

## 6) 高频场景如何映射到三层

* **机理闭环（PMSO/DPD/淬灭/对照）**：Layer3 `TASK_mechanism_*` → `PACK_mechanism_*`
* **合成 checklist**：Layer2 `day` + Layer3 `TASK_synthesis_*`
* **表征缺口审计**：Layer3 `TASK_characterization_audit_*`
* **CSV 作图/拟合 kobs**：Layer3 `TASK_figure_kobs_*`（产物写入 `assets/`）
* **阶段汇报 + ppt_pack**：Layer2 汇总 → Layer3 `PACK_stage_report_Rxx`

---

## 7) 最小落地（MVP）

只做 3 个闭环就能跑：

1. **Ingest**：Concept 下新建 Task（写 Claim + evidence）
2. **Plan**：生成 Protocol（steps + controls）
3. **Close**：写 Run（raw_data_paths + verdict）并导出 Pack（阶段汇报或机理包）

---

## 8) 约定与规范

* **任何 Claim 必须带 evidence**（无证据不入库）
* **任何 Run 必须带 raw_data_paths**（无路径不可“已完成”）
* **Pack 必须能回链到 task_refs**（否则不可称为交付物）
